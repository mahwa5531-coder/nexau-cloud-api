Server-lifecycle + runtime + accumulation round (2026-11-05): four new
scenario suites in `tests/` (catalog in `tests/README.md`), 27 new
scenario tests, all green hermetically and against real PostgreSQL 17
(`NEXAU_TEST_DATABASE_URL`-gated, the project's PG-integration
convention):
- `tests/boot_recovery_test.go` (B01–B09) — the process boundary: restart
  with in-flight reservations honored by the new process, orphaned
  reservations self-expiring after one ReserveTTL, boot-time outbox
  replay landing crashed records AND releasing the dead process's
  reservations, exactly-once replay under ambiguous commits, queue
  overflow spilling without blocking or dropping, SIGTERM drain (healthy
  and wedged-DB bounded-exit variants), Redis-restart amnesty with PG
  truth re-derivation, and the commit-before-hook crash window (bounded
  conservative double-count, self-healing). Drives the REAL
  metering.Recorder against an llm_calls fake with the exact SQL
  semantics (ON CONFLICT (call_id) DO NOTHING).
- `tests/runtime_operation_test.go` (R01–R09) — the running server:
  MaxDuration and idle-watchdog cuts metered honestly
  (cancelled/MAX_DURATION, failed/MODEL_TIMEOUT) with in-band client
  events; the usage cache's three disciplines (shields PG within TTL,
  bypasses at ≥95%, never stores at/over quota so recovery detection is
  immediate); admission estimates without max_tokens (prompt/4 + 2048)
  and with tools ((description+parameters+128)/4); SlotTTL crash
  recovery for leaked concurrency slots; the RPM window sliding with the
  honest retry-after.
- `tests/data_accumulation_test.go` (D01–D03) — window math at
  months-of-traffic scale: 150k-row exact sums and exact recovery row,
  40-way fan-out over a 100k-row history admitting exactly 12, and
  same-second bursts expiring as a step while spread calls drip.
- `tests/data_accumulation_pg_test.go` (P01–P05) — real engine: 1M
  accumulated rows (50k whale tenant + 950k noise) with exact sums, a
  Bitmap Index Scan on ix_llm_calls_tenant_time and a 16ms best-of-5
  admission read; the 400-day retention purge in bounded 5000-row
  batches; VACUUM reclaim (dead 60k→0, 32.9MB→15.6MB); InsertCalls
  idempotency at 2000-row scale; weight changes never rewriting history.
Findings en route, documented in the tests: at ~20% tenant share PG
deliberately picks a parallel seq scan for the window query (still
~130ms at 1M rows) — the index wins at production-shaped selectivity
(5%); miniredis TTLs expire on its virtual clock (FastForward), not
wall-clock sleep; time.Duration×time.Duration overflows int64 at
month-scale age ladders and seeded future rows until moved to plain
seconds.

Two real defects surfaced and were fixed:
- `internal/store/repos/auth.go` — `Rotate` wrote `replaced_by` BEFORE
  inserting the successor row; `refresh_tokens.replaced_by`'s immediate
  FK (SQLSTATE 23503) made EVERY refresh-token rotation fail with 500 on
  a real engine. The hermetic fakes and every existing suite were blind
  to it (no PG-gated test touched rotation). Fixed by inserting the
  successor first, then linking, inside the same transaction.
- `tests/boot_recovery_test.go` — the harness's AfterPersist closure
  raced the proxy assignment (the same publish-pattern bug main.go had
  already fixed for itself); caught by `-race` once scheduling shifted.
  Fixed with the same `atomic.Pointer` publish.

New suite: `tests/auth_pg_test.go` (P06) — refresh rotation on the real
engine: Issue → Rotate commits, the successor row lands, the consumed row
is linked, replay reads as reuse, and the family revocation sweep works.
Idempotent across runs (unique per-run token IDs; the seeded user is
FindOrCreate).

  around the session system, against the REAL auth.Service (state machine,
  single-use consumes, PKCE/nonce verification) with a scripted fake

  provisioning, unverified-email refusal, state replay + tx-cookie
  mismatch, nonce binding, single-use grants, desktop pairing (issue,
  two-channel race, 60s expiry), deactivation, token classification,
  refresh rotation + REUSE family revocation, expired-refresh non-purge,
  logout one/all, web-token blast radius.
- `tests/payment_journeys_test.go` (P01–P23) — every buyer journey
  against the REAL payment.Service (checkout idempotency, 3-legged
  confirm verification, webhook dedupe/converge/ordering, state machine)
  with a MockProvider running the REAL HMAC signature paths: catalog,
  idempotent replay, key reuse, unknown SKU, retry-storm budget, tampered
  amounts, confirm races/forgery/mismatch, webhook duplicate/out-of-order/
  forged/orphan/refund-no-reversal, IP flood budget, abandoned-checkout
  expiry, late capture on EXPIRED, failed-payment-then-clean-retry.
- `tests/plan_lifecycle_pg_test.go` (L01–L13) — what buying time does and
  what not paying does, against REAL PostgreSQL with the REAL repos SQL

All three green hermetically (A/P) and on real PostgreSQL 17 (L), and the
